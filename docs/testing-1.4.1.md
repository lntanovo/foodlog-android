测试日期：2026-10-28（Asia/Shanghai）。版本 1.4.1 / versionCode 8。发布批次：2026-10-29，使用同一已验证 APK；[GitHub Release](https://github.com/lntanovo/foodlog-android/releases/tag/v1.4.1) 提供安装包、源码 ZIP 和 SHA-256 校验文件，保留旧版本。

## 本次变化

- 设置 → 数据诊断：区分已吃/草稿、待补份量和餐食日期，点击日期可回到当日；显示本机数据集/修订/时区及备份状态，不自动修复或删除记录。
- 设置 → 历史保护副本：按时间浏览 recovery 目录已有副本；校验后预览记录数量及变化，可仅导出指定副本，或明确确认恢复。不自动删除任何保护副本。
- 本地与云端恢复：以本机 → 所选完整备份为方向，按记录身份列出新增/移除/变更；支持相同数量但日期、状态、份量或内容不同的记录。明细覆盖餐食、身体、每日记录/目标、食品/标签、计划、常用餐、来源及资料/时区。显示营养值按现有规则舍入，比较与保存使用原始值。
- 本地预览后若发生编辑，刷新差异并要求重新确认。真正写入时仍在 Repository 锁内检查数据集与修订；中断任务回到预览，不自动重复覆盖。

## 使用与安装

1. 在旧版设置中导出一份完整备份，保存到手机应用目录以外的位置。
2. 直接打开 1.4.1 APK 覆盖安装，不先卸载、不清除应用数据。
3. 安装后在设置 → 数据诊断核对已吃/草稿与历史日期。
4. 历史保护副本仅包含以前执行恢复时留下的副本；它不是每次编辑的撤销历史。查看或导出不会恢复，只有“确认替换并恢复”会替换本机数据。

## 范围边界

实体 vivo、Android 8–14、厂商后台调度、磁盘耗尽/硬件断电未在本轮实测。真实云账号流程未重跑，3 项参数测试按设计跳过；不能把状态机的模拟网络故障测试称为真实云联网验证。此前 vivo 餐食历史异常仍需手机原始导出定位，1.4.1 不宣称已修复未知根因。

代码复审核对：恢复身份/修订检查继续存在；差异只使用已校验数据，不触发合并或云端写入；诊断不包含令牌/密码；保护副本路径限定在本机 recovery 目录。CloudBase 技能中的 Web/Node 专属检查不直接套用到原生 Android。
