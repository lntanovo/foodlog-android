## 验收要求

### R1 覆盖安装保留数据

当用户直接覆盖安装新版时，应用必须保留原 applicationId、签名身份与数据库文件，并递增 versionCode；数据库变化必须显式迁移，禁止清库回退。升级与重启后，食品历史、餐食、草稿、身体记录、计划、每日快照、常用餐和来源记录应逐表一致。

### R2 账号可选，本机可离线使用

当用户未登录、登录失败、退出登录、令牌过期或网络不可用时，应用必须保留本机数据和完整离线记餐能力。登录成功本身不得触发清空、自动恢复或重新初始化业务数据库。

### R3 认证与私有归属

当用户登录时，应由托管认证服务验证用户名和密码，应用不得保存明文密码。会话应使用设备安全存储。服务端必须以已验证身份决定备份归属；账号A不得列出、读取或覆盖账号B的数据。管理密钥、个人记录与私有备份不得进入APK公共资源、Git或GitHub Release。

### R4 首次关联与版本化备份

当已有本机记录首次关联账号时，应用应让用户明确选择备份本机记录或查看云端备份，不能自动将本机内容覆盖到错误账号。每次成功备份生成独立版本，保留来源设备、服务端时间、摘要和校验信息；新备份失败不得删除上一份。

### R5 恢复前核对和保护

当用户选择云备份时，应用应下载到本机私有临时文件，验证账号归属、大小、SHA-256和数据格式，再展示日期范围及各类记录数量。仅在用户确认且恢复前保护备份成功后，才事务性替换本机数据。云端没有备份、下载失败或校验失败不得转换为空数据集并恢复。

当云端备份为空、明显更旧或记录更少时，应明确展示差异。两台设备各自的备份保留为不同版本；第一版不声称已自动合并两台设备上的不同修改。

### R6 任务恢复与账号切换

当上传、下载或预览期间应用重启或账号切换时，未完成文件不得作为成功备份显示。任务必须固定账号身份并在关键阶段重新验证；旧账号任务不能提交到新账号。重启后不得未经再次确认重放恢复操作。

### R7 国内服务与资源边界

账号和备份服务应在手机无需访问GitHub的情况下使用。当前未登录国内云服务账号，也未确定环境或费用；先登录查看资源和报价，再决定开通方案，不假定永久免费或擅自开通收费资源。

## 必须验证

1. 旧版写入合成数据 → 同签名覆盖升级 → 重启 → 逐表比较业务内容。
2. 独立设备A备份 → 设备B同账号登录 → 预览并恢复 → 全部业务实体及历史快照一致。
3. 本机与云端均有不同记录时，登录不自动覆盖；多个备份版本可选择。
4. 断网、错误密码、空云端、令牌过期、截断文件、校验错误、未来格式、存储不足和进程重启不破坏本机与已有云备份。
5. 两个合成账号的跨账号读写被服务端拒绝；切换账号后旧任务不能继续提交。
