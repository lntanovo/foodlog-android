# 账号与云备份设计（用户已确认并实施）

需求已确认：用户名密码登录、不可变版本云备份、新设备核对后恢复；不做双向自动合并。

## 资源方案

用户已确认复用已有的国内上海 CloudBase PostgreSQL 环境。环境与费用已核实，不购买新套餐、不启用自动续费或超限付费；账号标识、管理凭据及实际用量不写入公开源码。

食记新增独立资源：

- `public.foodlog_backups`：备份清单，仅已登录用户可插入、读取自己的备份。
- 私有 pgstore bucket `foodlog-backups`：完整压缩备份文件；路径为 `<uid>/<backupId>.foodlog.gz`。
- 专属于上述表和 bucket 的权限策略。原应用的数据表、文件区域、登录方式和套餐保持现有设置。

现有环境用户名密码认证已经启用。第一版提供 App 登录，账号可由用户在云后台预置或沿用同一环境已有账号。原生 HTTP 注册接口要求额外验证，不制作不能实际注册的用户名密码页面。

无需为本功能新购云服务器或启用短信服务。备份与登录消耗现有环境额度；体验期限、额度及停服边界需在开通时确认，不承诺永久免费。即使云服务不可用，设备上的记录仍独立保存。

## 手机端模块

1. `CloudAuthClient`：调用官方用户名密码登录、令牌刷新和登出接口；以安装时生成的随机设备 ID 标识会话。
2. `CloudSessionStore`：Android Keystore 加密保存令牌；不保存明文密码，不把令牌放入业务备份或界面重建状态。刷新串行执行并原子保存新令牌对。
3. `CloudBackupClient`：以用户令牌访问 PG 清单和私有存储；服务端按令牌身份确定归属，不使用管理员密钥。
4. `CloudBackupViewModel`：持久化非敏感任务日志、账号会话代次、私有临时文件和阶段；断网、重建或切换账号后阻止误提交。
5. 设置页增加“账号与云备份”：登录、备份本机记录、查看备份、下载并预览恢复、退出登录。原本的本地导出与恢复继续可用。

本地业务数据仍使用原 Room 数据库。认证、私有临时文件和任务日志独立保存；登录成功不调用业务恢复或数据库重建。

## 认证 API

国内基础地址从已确认环境配置生成：`https://<envId>.api.tcloudbasegateway.com`。

| 用途 | 官方接口 | 请求要点 |
|---|---|---|
| 登录 | `POST /auth/v1/signin` | JSON `username`、`password`；随机持久 `x-device-id` |
| 刷新 | `POST /auth/v1/token` | `grant_type=refresh_token`、`refresh_token` |
| 登出 | `POST /auth/v1/user/signout` | 用户 Bearer token；本机云会话退出不删除业务数据 |

依据官方 Auth OpenAPI 实现，不在 APK 中放管理 API Key。旧刷新令牌失效后只能使用新令牌；认证失败提示重新登录，不影响本机使用。

## 备份清单

计划字段：备份 UUID、服务端归属、服务端创建时间、私有对象路径、SHA-256、压缩字节数、App/备份格式版本、来源设备别名、数据集标识、记录数量和日期摘要。

- `owner_id text NOT NULL DEFAULT auth.uid()`；身份由数据库决定。
- `backup_id uuid PRIMARY KEY`；每次备份独立生成。
- 用户角色只授予 INSERT/SELECT；第一版不提供覆盖或删除旧版本的入口。
- RLS 的 SELECT 和 INSERT 条件均为 `owner_id = auth.uid()`；客户端不能靠伪造 owner 访问其他人的内容。
- 私有文件策略同时校验 bucket 与首段路径 UID，不扩大现有存储区域的权限。
- 新建后读取真实 schema/权限，并使用两个合成账号做越权测试；管理员查询成功不能替代用户身份验证。

## 备份流程

用户确认账号与本机记录的关联 → 固定账号 UID、会话代次和备份 ID → 通过现有 `Repository.writeBackup` 生成私有 GZIP → 计算 SHA-256 与摘要 → 上传新对象 → 校验成功后插入清单 → 显示备份成功。

未上传完成的文件不显示为可恢复版本。清单失败可重试，已有成功版本不受影响；对象名不使用 upsert，重试同一 ID 时先核对服务端结果，防止重复或覆盖。所有关键步骤检查账号和会话代次，退出或切换账号即停止旧任务。

## 恢复流程

用户选择备份 → 固定当前账号 → 获取短效私有下载地址 → 不携带登录令牌跨域转发 → 流式下载私有临时文件 → 核对大小、SHA-256、账号归属、格式与解压上限 → 展示本机和备份记录数量/日期 → 用户明确确认替换 → 成功创建并验证恢复前本机保护备份 → Room 事务恢复 → 显示结果。

继续复用 `Repository.readBackup`、`restore` 和现有恢复预览。云端没有备份与网络错误分开处理；任何错误不得生成默认空 Dataset。恢复步骤被打断后，不在重启时悄悄重放。

恢复前本机保护副本将加强为：临时文件写入、落盘、校验、原子改名；保护副本失败则停止恢复。云服务和本机保护副本分别解决跨设备取回与误恢复回退，不能互相替代。
